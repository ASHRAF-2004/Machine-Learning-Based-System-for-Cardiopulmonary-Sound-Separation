# Presentation Guideline And Rubric Summary

Source: `docs/CW Project 2530 - CSE 6234 SDv5.pdf`

## Assignment Purpose

The CSE 6234 Software Design assignment assesses whether the group can demonstrate good software design qualities in a working prototype system, supported by a clear group presentation and individual contribution reflection.

## Required Submission Evidence

- Working prototype software.
- Live/group presentation.
- Slide presentation.
- Source code and software instructions.
- Self-reflection report from each student.

## Required Slide Content

The slide presentation should cover:

- System objectives.
- System scope.
- System overview.
- Component-level diagram.
- Software architecture.
- Input and output.
- Whether the solution was achieved.
- Work segregation.
- Self-reflection report for each student:
  - contributions,
  - challenges faced,
  - areas for improvement.

## Prototype Requirements

The working prototype should show:

- UI layer.
- Business logic layer.
- Database layer.
- Functional workflow related to the chosen domain.
- Software design concepts, principles, and design patterns applied to the prototype.

## Main Rubric Areas

### Working System And Prototype

Key assessment points:

- Functionality and working software.
- Applied software design patterns.
- User interface design.
- Proposed system architecture.
- Code quality, organization, readability, naming, comments, and modularity.
- Innovation and creativity in addressing the problem.

### Group Presentation And Slide Presentation

Key assessment points:

- Understanding of design patterns and component-level design.
- Clear documentation explaining design choices, functionality, and future improvements.
- Clear prototype presentation.
- Team collaboration with clearly defined roles.
- Presentation clarity and ability to answer questions.

### Individual Contribution And Presentation

Key assessment points:

- Participation and engagement.
- Quality of individual contribution.
- Initiative and responsibility.
- Communication skills.
- Clear fair share of work.

## Presentation Strategy For This Project

For a 10-minute presentation, the deck should stay concise:

- Use one slide each for problem/objectives, scope/features, architecture, component design, design patterns, prototype workflow, solution/future work, work segregation, and self-reflection.
- Use short phrases instead of paragraphs.
- Show diagrams only when they are readable; otherwise use simplified visual blocks.
- Emphasize the working FastAPI prototype, real NeoSSNet separation workflow, SQLite history, and maintainable design patterns.
- Give each group member a speaking part and a short self-reflection.

## Rubric Alignment Checklist

- Working prototype is explained.
- UI, business logic, ML, storage, and database layers are shown.
- Input and output are clear: mixed WAV input, separated heart/lung WAV outputs, and SQLite history.
- Component-level design is shown with service and ML components.
- Software architecture is shown with layers.
- Design patterns are mapped to project classes.
- Team roles and individual reflections are included.
- Future improvements are honest and realistic.
